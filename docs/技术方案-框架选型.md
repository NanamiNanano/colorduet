# 技术方案：复用 Chaquopy + WebView（替代 Kivy/Buildozer）

> 触发原因：查看 `E:\DeekSeek_Project\e2046价格监测` 后，发现本项目已有一条**验证过的 Python→APK 流水线**。
> 结论：放弃原 PRD 第 7.1 节的 Kivy 方案，复用该流水线。
> 日期：2026-10-29　状态：待确认

---

## 1. 结论

| 项 | 原方案（PRD v0.1） | 新方案 |
| --- | --- | --- |
| 桌面/Android 框架 | Kivy + KivyMD | **HTML/CSS/JS 前端 + Python 本地服务** |
| 打包 | Buildozer / python-for-android | **Gradle + Chaquopy**（照抄 e2046） |
| CI | 新写 buildozer workflow | **复用 `android/.github/workflows/build.yml`** |
| UI 绘制 | Kivy Canvas / 自绘控件 | **Canvas 2D**（色环、放大镜、图片变换） |
| 数据层 | Kivy 存储 + json | Python 标准库 + json（同 e2046） |
| 构建时长 | 首次 20–40 min，失败率高 | **5–10 min，可重复**（你 README 里实测过） |

一句话：**你已经把最难的那段（Python 打进 APK）走通了，没必要为这个 App 再走第二遍。**

## 2. 五条决定性理由

### R1 构建风险从"未知"变"已知"
Buildozer 在 Windows 上根本不能跑，p4a 对 Python 3.12 的支持要现场试；而 Chaquopy 这条链路你已经出过包、签过名、装过机。**这是本项目唯一的高危项，直接消除。**

### R2 中文输入（这条最容易被低估）
色卡命名必须支持中文。Kivy 在 Android 上的文本输入走 SDL2，**中文输入法的候选词/组合输入历来是坑**，很多 Kivy 安卓应用干脆不能打中文。
`<input type="text">` 是系统原生输入框，中文、语音输入、剪贴板全部白拿。**光这一条就足以定方案。**

### R3 文件选择与导出
- WebView：`<input type="file" accept="image/*">` + `WebChromeClient.onShowFileChooser`（约 20 行 Java）→ 直接调起系统相册，**零权限**。
- 导出：Python 写文件到私有目录，再用 `FileProvider` + `ACTION_SEND` 分享。
- Kivy：要自己用 jnius 拼 `ACTION_OPEN_DOCUMENT`、处理 `on_activity_result` 回调、还要处理授权 Uri 的生命周期。**约 150 行易错代码。**

### R4 手势
双指缩放、平移、长按放大镜、列表拖拽排序 —— Pointer Events 全是标准做法，代码量小、行为可预测。Kivy 的 `Scatter` 可用但拖拽排序要自写，且触摸事件与滚动容器冲突时很难调。

### R5 已有的东西直接搬
见第 4 节。你的 `build.yml`、固定签名 keystore、`MainActivity` 壳、`bridge.py` 思路、启动脚本、目录约定，全部可复用。

## 3. 架构

```
┌───────────────────────────────────────────────┐
│ WebView（Android） / 浏览器（PC）              │
│  index.html + app.js + style.css              │
│  · Canvas 2D：色环、放大镜、图片、色板点云      │
│  · Pointer Events：缩放/平移/长按/拖拽          │
│  · 色彩数学（OKLCH / RYB / ΔE）全部在 JS 里    │
└───────────────┬───────────────────────────────┘
                │ HTTP /api（localhost，仅本机）
┌───────────────┴───────────────────────────────┐
│ Python（标准库 http.server，无 pip 依赖）       │
│  · 静态文件服务                                 │
│  · 项目 JSON 读写、图片落盘（base64 解码）      │
│  · 导入/导出 zip（zipfile 标准库）              │
└───────────────┬───────────────────────────────┘
                │ 文件系统
┌───────────────┴───────────────────────────────┐
│ PC: ./data/          Android: getFilesDir()    │
└───────────────────────────────────────────────┘
```

**关键分工**：交互与计算在前端（要 60fps），**持久化在 Python**（要可靠）。
这样 APK 里**不需要 numpy / Pillow / 任何 pip 包**，Chaquopy 构建又快又稳 —— 和 e2046 完全一致的取舍。

## 4. 从 e2046 能直接复用什么

| 资产 | 路径 | 复用方式 |
| --- | --- | --- |
| CI 流水线 | `android/.github/workflows/build.yml` | 整份拷贝，改 artifact 名 |
| 签名密钥 | `android/app/e2046.jks` + `signingConfigs.stable` | **照搬结构，换一个新 keystore**（别共用） |
| Gradle 配置 | `android/app/build.gradle` | 改 `namespace`/`applicationId`/版本号 |
| WebView 壳 | `MainActivity.java` | 改 URL 与按钮；新增 `onShowFileChooser` |
| Python 桥 | `bridge.py`（配置/路径落到私有目录） | 改为项目目录初始化 |
| 启动/刷新机制 | 页面按钮触发 HTTP 接口 | 同构 |
| Windows 启动方式 | `.bat` + `python -m ... serve --open` | 同构（可复用 `一键更新价格.bat` 的写法） |

> **务必继承的一条经验**：固定 keystore。你 e2046 的 `build.gradle` 里已经注释清楚了原因 —— 每次构建换签名会导致"覆盖安装报签名不一致、只能卸载重装、数据全丢"。**个人自用项目里这条比什么都重要。**

## 6. 数据与存储

| 环境 | 根目录 | 说明 |
| --- | --- | --- |
| PC | `./data/` | 与 e2046 的 `data/` 同构，直接可见可备份 |
| Android | `getFilesDir()/colorpick/` | 私有目录，卸载即失；靠"导出 zip"做备份 |

- 图片以 **base64 POST 给 Python**，Python 用 `base64` 标准库解码落盘（无需 Pillow）。
- 缩略图由前端 Canvas 生成后一并上传。
- 项目结构：`projects/<id>/project.json + images/*.jpg`（多图）。

**因为不上架**，可以把"导出备份"做成首页显眼按钮：一键把整个 `data/` 打包 zip 发到微信/网盘。个人使用场景下，**这比任何云同步都靠谱**。

## 7. 代价：我会丢掉什么

| 丢掉的东西 | 影响评估 |
| --- | --- |
| Python 作为"主体语言" | Python 退化为存储层。**但数学仍可用 Python 做基准实现**（本仓库已有），前端只做翻译与验证 |
| 原生控件手感 | WebView 滚动/点击有 1–2 帧延迟，个人使用完全可接受 |
| Kivy 学习的沉没成本 | 你尚未投入，无损失 |
| 单语言项目 | 变成 JS + Python 两套；但 e2046 已经是这样，你熟悉 |
| 前端逻辑的可测性 | 用 `tests/golden.json`（Python 生成）+ 浏览器 `selftest.html` 比对断言解决 |
