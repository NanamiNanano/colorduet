## 1. 结论（三句话）

1. **两个环的本质不是"加色/减色"，而是"光的混合"与"颜料的混合"**。前者补色是红↔青，后者是红↔绿。若按字面做成 CMY，第二个环会与第一个环补色重合，失去意义。
2. **光色环的色相角改用 OKLCH**（感知均匀），否则"色相差几度"在不同色区视觉权重不同，比较功能不可信；颜料环用 Itten 12 色体系。
3. **主界面回答"离参照多远"，不回答"值是多少"**：双标记环 + 结论徽标 + 四项差值，绝对值折叠在详情里。

### 1.1 相对 PRD v0.1 的改动清单

| # | PRD v0.1 | v0.2 方案 | 原因 |
| --- | --- | --- | --- |
| D1 | `RGB / RYB 双色环` | 「光色环 / 颜料环」，英文 Light / Pigment | 避免"减法=CMY"的语义陷阱 |
| D2 | 色相角 = HSV 的 H | 光色环用 OKLCH 的 h；颜料环用颜料色相角 | 等角必须等于等感知差 |
| D3 | 主显示 RGB 三元组 / RYB 三元组 | 主显示"色相/明度/彩度 是否一致"；三元组折叠 | 用户明确不需要绝对值 |
| D4 | 无参照概念 | 新增「参照色」+ 对比浮层 + 徽标 | 比对是核心诉求 |
| D5 | 色卡卡片显示数值（随模式切换） | 色块 + 名称 + 结论徽标 + 可选数值 | 同上 |
| D6 | RYB 数值口径 0–100 | 颜料坐标（色相角 + 纯度），绝对量降为 P2 | 口径争议消失，先不做 |
| D7 | 明度滑杆 0–100% | 明度轴统一用 OKLab L（0–1，内部），UI 可显示百分比 | 一套明度，两个环共用 |

## 2. 概念澄清：三种"补色"、两种"混合"

"补色"在中文里被三种不同关系共用，这正是最容易设计错的地方。

| 叫法 | 定义（怎么才算补色） | 红色对面 | 典型来源 |
| --- | --- | --- | --- |
| **光学补色** | 光相加后变白 | 青 | 屏幕、灯光、视觉后像 |
| **颜料补色** | 颜料相加后变暗浊/中性 | 绿 | 绘画、调色、印刷（传统） |
| **对立色** | 神经通道的对抗（Hering） | 绿（但黄↔蓝） | NCS、色彩心理学 |

**关键区分：**

- 加色 RGB 与减色 CMY 是**同一个对立关系的两面**（CMY 就是 RGB 的反相），补色对完全相同（红↔青、绿↔品红、蓝↔黄）。**所以"减法模式"若做成 CMY，和第一个环没有区别。**
- **RYB** 是美术教育里经验总结出的颜料混合模型，它把补色重新配成 红↔绿、黄↔紫、蓝↔橙，这才是与第一个环真正互斥的第二套世界观。
- 严格说 RYB 不是物理上的减色混合（那是 CMY），它是**经验模型**。文档与 UI 中应称"颜料混合模型"，不要称"减色模型"，以免和印刷色彩管理混淆。

### 2.1 两个"镜像例子"（产品文案可直接用）

| 混合 | 光（相加） | 颜料（相加） |
| --- | --- | --- |
| 黄 + 蓝 | 白（**是**补色对） | 绿（**不是**补色） |
| 红 + 绿 | 黄（**不是**补色） | 暗浊灰（**是**补色对） |

同一对颜色，在两种混合下"是否互补"的答案是反的。**这就是双环存在的唯一理由**，也是引导页第一屏最好的例子。

## 3. 两个环的定义

两环共用同一套几何骨架，减少用户的切换成本：

```
        ┌─ 明度轴（右侧竖直滑杆，0–100%，两环共用）
        │
   ┌────┴─────┐
  ╱  色相环    ╲    角度 θ：绕环一周，标注 6 个锚点
 │    ●标记    │    半径 ρ：0=中心（中性） 1=最外（最艳）
  ╲           ╱     标记位置 = (θ, ρ)，颜色 = f(θ, ρ, L)
   └──────────┘
```

### 3.1 光色环（Light）

| 属性 | 定义 |
| --- | --- |
| 色相 θ | **OKLCH 的 h**（感知均匀）。0° = 红，角度增长方向与 OKLCH 一致（h≈29° 红、110° 黄、142° 绿、264° 蓝、328° 品红附近，具体锚点由算法定） |
| 半径 ρ | 该 (h, L) 下 sRGB 色域内最大彩度 C 的归一化值：ρ=1 即"这一色相最艳能吃到的程度" |
| 颜色 | 由 (L, C=ρ·C_max(h,L), h) 反算 sRGB，越界则沿色域边界裁切 |
| 6 锚点标注 | 红 R / 黄 Y / 绿 G / 青 C / 蓝 B / 品红 M |
| 补色对 | R↔C、Y↔B、G↔M（对径即补色，误差 ≤ 1°） |

**为什么不用 HSV**：HSV 的 H 在视觉上极不均匀（绿区宽、黄区窄），"色相差 10°"在绿区几乎无感、在黄区却跳变。既然产品的核心是"判断色相是否一致"，角度必须与感知差成正比。
**代价**：环不会像 HSV 那样整圈都艳（低明度时彩度上限收缩），需要接受。若测试发现用户觉得"环不够艳"，再提供设置项切回 HSV 显示，但**比较数值仍走 OKLCH**。

### 3.2 颜料环（Pigment）

| 属性 | 定义 |
| --- | --- |
| 色相 θ | 颜料色相角，0° = 红，60° 橙，120° 黄，180° 绿，240° 蓝，300° 紫（Itten 12 色，30° 一档，共 12 个刻度） |
| 半径 ρ | 颜料纯度（含白/黑的稀释程度）：1 = 纯颜料，0 = 中性灰 |
| 颜色 | 由颜料立方体（RYB 三线性插值）生成，见 PRD §4.4 |
| 补色对 | R↔G、Y↔V、B↔O（对径即补色） |
| 与光色环的关系 | 几何相同、映射不同。切换时环的颜色与标签**渐变过渡**，让用户看到"同一个位置，含义变了" |

### 3.3 明度轴（两环共用）

- 统一使用 **OKLab 的 L**（0 = 黑、1 = 白），两环共享同一根滑杆、同一数值口径。
- UI 显示为百分比；颜料模式下可加一行小字提示"≈ 加白 20%"（可选，P2）。
- 明度是唯一在两环间**完全可比**的维度，因此"明度是否一致"的判定不随模式变化。

## 4. 比较机制（本方案的核心）

### 4.1 参照色（Reference）

- 色卡列表中任一色可长按 →「设为参照」，参照色在列表与环上均显示为**空心圈**。
- 参照可随时更换、可取消；默认无参照（此时不显示差值面板，只显示绝对位置）。
- 从图片取色时，自动以"当前选中色"为参照（若有），实现"边看边比"。

### 4.2 双标记环

- 同一环上画两个标记：参照色（空心圈 + 细描边）、当前色（实心点）。
- 两点之间画一条**弧线**并标注色相角差（可关闭）。
- 两点半径差用**径向短线**表示彩度差。
- 标记重合（ΔE 极小）时，当前色标记外扩 2 px 避免完全遮盖。

### 4.3 差值面板（定性优先，定量可选）

| 维度 | 显示形式 | 一致判定（默认阈值，可调） |
| --- | --- | --- |
| 色相 | 同色相 / 邻近 / 中差 / 对比 / 互补 + 角度差 | ≤ 4° 判"一致" |
| 明度 | 更亮 / 更暗 + ΔL | \|ΔL\| ≤ 0.03 判"一致" |
| 彩度 | 更艳 / 更灰 + ΔC | \|ΔC\| ≤ 0.02 判"一致" |
| 总色差 | ΔE（OKLab 欧氏距离；可切换 CIEDE2000） | < 0.02 肉眼难辨；0.02–0.05 接近；> 0.05 明显不同 |

**色相档位（按角度差）**：≤4° 同色相 / 4–20° 邻近色 / 20–60° 中差 / 60–120° 对比色 / >120° 互补色。
（阈值来自常见配色理论的分档，需在实际使用中校准；应在设置里可调。）

### 4.4 结论徽标（列表卡片用）

一行两三个字的结论，是比数值更快的答案：

```
┌─────────────┐
│ ██████████  │  ← 色块
│ 雾蓝        │  ← 名称
│ 色相 ✓ 明度 -12 │  ← 徽标（相对参照）
└─────────────┘
```

- 三态：`✓ 一致` / `≈ 接近` / `✗ 不一致`，图标 + 文字双重编码（色弱可用）。
- 点击卡片展开详情：绝对值（HEX / RGB / 颜料坐标）折叠在此，专家需要时可看。

### 4.5 同一个问题，两个坐标系（双环的真正价值）

"这两个色的色相是否一致？"——答案取决于你在问哪个世界：

| 场景 | 用哪个色相判定 | 为什么 |
| --- | --- | --- |
| 屏幕配色、UI、灯光 | 光色环的 OKLCH 色相 | 决定"看起来像不像同一个色系" |
| 调色、找颜料、定笔号 | 颜料环的颜料色相 | 决定"该往哪个方向加颜料" |

两个色素可能在屏幕上"色相一致"，但颜料色相相差较大（因为彩度/明度不同，颜料反解结果不同）。**界面需要允许用户在同一份数据上切换这两个镜头**，而不是永远只给一个答案。切换时徽标应即时重算，并可用一行小字说明"以颜料色相判定"。

## 5. 新增需求（并入 PRD §5）

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-C1 | P0 | 参照色设定/更换/取消（列表长按、环上点选） | 设为参照后，所有相关标记与徽标 200 ms 内更新 |
| FR-C2 | P0 | 差值面板：色相/明度/彩度三项 + 总色差，定性结论优先 | 与参考实现对比，ΔL/ΔC 误差 ≤ 0.005，色相角误差 ≤ 1° |
| FR-C3 | P0 | 双标记环 + 弧线 + 径向彩度线 | 弧线角度标注与面板数值一致（±1°）；标记缩放平移下不漂移 |
| FR-C4 | P1 | **色板概览环**：把列表里所有色以点云形式画在同一个环上（点大小=彩度，点色=真实色） | 一眼可见"配色集中在哪个色域、缺哪个色相"；50 个点仍流畅 |
| FR-C5 | P1 | 吸附：拖动当前色时，接近参照色相（±3°）或明度（±0.02）自动磁吸 | 吸附阈值可关；吸附有轻微触感/视觉反馈 |
| FR-C6 | P0 | 一致性徽标（✓/≈/✗ 三态 + 短文本） | 与差值面板判定一致；不依赖颜色单独传达状态 |
| FR-C7 | P1 | 模式切换时，环颜色/标签/徽标同步过渡 | 过渡时长 200–300 ms；无闪烁 |
| FR-C8 | P2 | 配色检测：色板环上标出"缺失的色相区间" | — |

**FR-C4（色板概览环）值得单独强调**：它把"色环"从输入控件升级成"诊断工具"——用户不需要任何数值，就能看出自己这套配色偏在哪、缺什么。这比任何数字都符合"我要相对位置"的诉求。

## 6. 数据模型改动

```json
{
  "rgb": [122, 158, 189],          // 唯一真值
  "oklch": [0.680, 0.055, 232.4],  // 派生（可缓存，加载时重算）
  "pigment": { "hue": 214.0, "purity": 0.42 },  // 派生
  "ref": "c_03"                    // 参照色 id（项目级，非单色属性）
}
```

原则：

- **只存 RGB（+ 图片路径/坐标）**，其余全部派生。算法升级后重算即可，不存在"旧数据对不上"的问题。
- 参照色是**项目级**状态（`project.compare_ref`），不是每个色各存一个。
- 不存"一致性判定结果"（随时可算，避免缓存失配）。
- 阈值（4° / 0.03 / 0.02 / ΔE 分档）放设置层，带默认值，便于后续调参而不用改数据。

## 7. 技术落地要点

| 项 | 说明 | 成本 |
| --- | --- | --- |
| OKLab/OKLCH 换算 | 纯矩阵 + 立方根，约 40 行；批量向量化 | 低，无第三方依赖 |
| 色域裁切 | 给定 (h, L) 求最大 C：二分或直接采样 sRGB 边界；离线预计算 LUT 可加速 | 中，需缓存 |
| 光色环纹理 | 逐像素求 (h, C_max, L) → sRGB；128² 纹理用 numpy 一次算完 | 低（2–6 ms） |
| 颜料反解 | 立方体网格最近邻 + 局部细化（PRD §4.5） | 中（已规划） |
| ΔE 计算 | OKLab 欧氏距离（默认）；CIEDE2000 作为可选项 | 低 |
| 色板点云 | 环上叠 N 个 dot，普通 Canvas 即可 | 低 |

**风险点**：OKLCH 环在低明度时彩度收缩明显（L=0.2 时几乎无彩色），环会看起来"灰掉"。这不是 bug，是物理事实。需在 UI 上给出解释（明度滑杆拖动时环整体变暗、彩度上限同步收缩），避免用户以为取色失败。

## 8. 我评估过但**不采用**的方案

| 方案 | 优点 | 否决理由 |
| --- | --- | --- |
| 只做一个环 + 补色标注切换 | 实现最省 | 补色关系是环的骨架，不是标注；做不到"同一位置两种含义" |
| 双环 = RGB 环 + CMY 环 | 术语上最"标准" | 两者补色关系完全相同，等于做两个一样的环 |
| Munsell 体系 | 最科学（色相/明度/彩度三维独立） | 补色关系不是画家要的（5R↔5BG）；完整色卡数据量大，移动端不现实 |
| NCS | Hering 对立色，红-绿对位正确 | 黄↔蓝 与画家要的黄↔紫 不符；商业标准需授权；四象限太粗 |
| 双 3D 球/双锥体 | 三维信息完整 | 手机上不可操作，标记互相遮挡，取色精度极低 |
| 只用 ΔE00 不用双环 | 数值最严谨 | 回答不了"往哪个方向调"——而这正是用户要的 |
| 色相用 HSV 但显示 OKLCH 数值 | 兼顾好看与可比 | 界面位置与数值不自洽，用户会感到"对不上" |

## 11. 决策记录（2026-10-29，附实测图）

### 11.1 Q1 光色环的色相基准 —— 实测后改判

原推荐"OKLCH + 固定明度"。**渲染实测后发现这个方案不能用**：

| 方案 | 图 | 实测结论 |
| --- | --- | --- |
| A：HSV | `preview/01` | 6 主色正好每 60°，好看好找；但相邻 30° 的色差在 **6.1 ~ 40.3** 之间跳（6.6 倍），"角度 = 感受"完全不成立 |
| B：OKLCH + 固定明度 L=0.72 | `preview/01` | 色差曲线很平（13.8 ~ 19.8，1.4 倍），但**整圈发闷**：固定明度时"红"只能是珊瑚粉，拿不到大红；主色标签挤在 81/33/52/69/64/61 度 |
| **E：OKLCH 尖点彩度 + 真实色相角** | `preview/05` | **既艳又均匀**，代码最少；代价是标签不等距、版式不对称 |
| D：尖点彩度 + 6 等分角（warp） | `preview/05` | 版式对称，但分段线性 warp 在 6 个主色处留下**肉眼可见的折痕** |

**改判为 E。** 关键认识：HSV 之所以显得艳，是因为它的外圈正好落在 sRGB 色域的**尖点（cusp）**上；OKLCH 环要既均匀又艳，就必须也走尖点，而不是固定明度。

**修正后的光色环定义（替代 3.1）**

| 属性 | 定义 |
| --- | --- |
| 色相 θ | OKLCH 的 h（真实角），0° = 正右，逆时针增大 |
| 半径 ρ | 0 = 中性灰，1 = 该色相的色域尖点（最艳） |
| 颜色 | 由 (h, ρ) 在 OKLab 中插值到尖点：`L = lerp(0.72, L_cusp(h), ρ)`、`C = ρ·C_cusp(h)` |
| 明度 | **由独立的滑杆对整环做加白/加黑**（tint/shade），环本身永远保持最艳（见 `preview/03`） |
| 主色标签位置 | 红 29°、黄 110°、绿 142°、青 195°、蓝 264°、品红 328°（不等距，是真实感知） |

> 这个改动同时解决了两件事：环不再发闷；**明度滑杆与颜料环的"加白/加黑"语义统一**，与画家直觉一致。

## 11.6 最终决定：光色环采用 HSV（2026-10-29）

**决定**：光色环用 HSV（方案 A），理由是"绘画时的常用方案、比较熟悉"。曲高和寡的感知均匀方案放弃。

### 接受这个决定的代价（写下来，免得以后反复怀疑）

HSV 的色相角不等距：绕环每 30°，人眼感受到的色差在 **6.1 ~ 40.3** 之间（实测，见 `preview/02`）。后果是 **±3° 的严格阈值在不同色区松紧不一**——绿色区 3° 几乎看不出，黄/品红区 3° 相当明显。
这不是 bug，是 HSV 的固有性质；我们选择"与所见一致"而不是"与感知一致"。

### 配套的三项口径（把代价控制住）

| 维度 | 用什么算 | 阈值 | 理由 |
| --- | --- | --- | --- |
| 色相是否一致 | **当前环的色相角差**（光：HSV 的 H；颜料：颜料色相） | ≤ 3° | 与用户在环上看到的夹角一致，不会"看着差挺远却判一致" |
| 明度是否一致 | **感知明度 L\***（0–100，OKLab 推导） | ΔL\* ≤ 2 | "明度"问的是视觉亮度；用 HSV 的 V 会得出"红和黄的 V 都 50% = 一样亮"这种反直觉结论 |
| 彩度是否一致 | OKLCH 的 C | ΔC ≤ 0.015 | 环上半径是"相对饱和度"，跨色相比较会骗人，用绝对彩度 |
| 总差异 | **CIEDE2000** | < 2 肉眼接近；2–5 可辨；> 5 明显不同 | 唯一一个"感知正确"的兜底指标，用来对冲上面色相口径的失真 |

**界面表现**：徽标同时给"色相 ✓ ±3°"和"总差 ΔE 1.8（接近）"。当两者打架时（例如色相差 2° 但 ΔE 只有 0.4，说明实际看不出来），**以 ΔE 为准显示"接近"**，并在提示里说明原因。这条规则让 ±3° 的失真不会直接产出错误结论。

### 滑杆与环的对应（最终形态）

| | 光色环（HSV） | 颜料环（RYB） |
| --- | --- | --- |
| 角度 | HSV 的 H，红/黄/绿/青/蓝/品红 每 60° | 颜料色相，红/橙/黄/绿/蓝/紫 每 60° |
| 半径 | S（饱和度），中心 = 白 | 纯度，中心 = 中性灰（**需校正成真灰**） |
| 滑杆 | V（明度），中心为白、外圈最艳 | 加黑程度，100% = 原色 |
| 两环共性 | 半径 = 彩度，滑杆 = 明度。同一根滑杆，各自按自己的模型解释 | 同 |
